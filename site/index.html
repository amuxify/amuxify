amuxify

The ingest gate for self-hosted media.
Verify, sanitize, normalize, prove.

amuxify is a command-line tool that sits between “downloaded or purchased” and “in the Plex or Jellyfin library”. It runs once per file, changes nothing it cannot prove is safe, and exits with a verdict your download client, Sonarr, Radarr or cron job can act on. Linux, macOS and Docker.

Install Source on GitHub Documentation 
$ amuxify scan ~/incoming
PASS  /home/me/incoming/Show.S01E01.mkv
WARN  /home/me/incoming/Movie.2019.mkv
      WARN  LINK_IN_TAG        1 link(s) in metadata: tag COMMENT: http://tracker.example/x
BLOCK /home/me/incoming/Movie.2019.Sub.mkv
      BLOCK ATTACH_EXEC        attachment #1 "font.ttf" (font/ttf, 71 KiB) contains executable PE/DOS executable

BLOCK: 3 file(s) BLOCK=1 PASS=1 WARN=1

It is not a transcoder, a renamer or a library manager. Streams are never re-encoded. After a remux, every kept stream is hashed and compared with the source before the output is moved into place.

What it catches

Files from Usenet, torrents and untrusted storefronts arrive with more than video and audio in them. amuxify looks for the things a media server will happily import and a virus scanner will not flag:

  • Executable payloads hiding as font or image attachments inside an MKV, and polyglot files that are a valid video and a valid ZIP, PE, ELF or script at the same time.
  • Tracker URLs and release-group links in tags, the title, chapter names and subtitle text.
  • Purchase identifiers in MP4 and M4V metadata atoms (account name, purchase date, store IDs) and XMP blocks.
  • Dangerous sidecars next to the video: .lnk, .url, .exe, .scr, .bat, .ps1 and friends.
  • Mislabeled and broken files: the extension does not match the content, the container is truncated, it reports no duration, or it does not decode.
  • Filenames with right-to-left override or zero-width characters, and double extensions.

Then it fixes what a policy allows it to fix: strips metadata and extended attributes, drops commentary tracks, unwanted languages or attachments, sets language and default flags, and rebuilds the file as a clean Matroska container. Nothing is re-encoded.

Install

# release binary, Linux and macOS (verifies the SHA-256 checksum)
curl -fsSL https://raw.githubusercontent.com/amuxify/amuxify/main/install.sh | sh

# Homebrew
brew install --cask amuxify/tap/amuxify

# Docker, run as the uid that owns the library, never root
docker run --rm -u 1000:1000 -v /srv/media/incoming:/data ghcr.io/amuxify/amuxify scan /data

amuxify needs MKVToolNix 50 or newer and ffmpeg 4.4 or newer on the same machine. exiftool and clamscan are optional. Run amuxify doctor to see what is missing. The install guide covers package names per distro, pinning a version and the Docker image.

Input containers: MKV, WebM, MP4, M4V, MOV, AVI, MPEG-TS, M2TS, MPG, VOB, FLV. Output is always Matroska, written by mkvmerge. ffmpeg is used for probing, hashing and decode checks, never for writing an MKV.

Verdicts and exit codes

VerdictExitMeaning
PASS0Nothing to report
WARN1Something to know about; file is usable
usage2Bad arguments or missing tool
FAIL3Integrity problem: unparseable, truncated, hash mismatch, mislabeled
BLOCK4Security problem: executable payloads, polyglots, bidi names, blocked sidecars. Never overridable
interrupted130Ctrl-C or SIGTERM; temp files removed

The worst verdict of the run becomes the exit code. With --json the full report is printed instead, using the same codes. The JSON format is described in docs/report.md.

Profiles

A profile is a TOML file that says what to keep, what to drop and how hard to verify. Four are built in and homelab is the default. Unknown keys are rejected, so a typo cannot silently widen a policy.

ProfileLanguagesChaptersFontsCommentaryLinks / provenanceVerify
homelabkeep allkeepkeep if text subskeepwarnquick
animekeep all, prefer originalkeepkeepdropwarnquick
archiveEnglish onlydropdropdropfailquick
strictEnglish onlydropdropdropfailfull + ClamAV
 
amuxify profile show homelab > my.toml   # edit, then
amuxify --profile ./my.toml remux ~/incoming

All keys are described in docs/profiles.md.

Safety guarantees

  1. Never overwrites an existing path; a collision is a FAIL.
  2. Writes a temp file beside the destination, fsyncs, then renames. Never across filesystems.
  3. Symlinks are skipped per file, never followed, never abort a tree.
  4. Every ffmpeg and ffprobe call carries -protocol_whitelist file,pipe and a timeout.
  5. Every kept stream's SHA-256 matches source and output, or the output is deleted.
  6. In-place mode preserves owner, group, mode and mtime.
  7. Extended attribute removal touches only user.* (Linux) and com.apple.* (macOS).
  8. --verify none is refused together with --in-place.
  9. BLOCK cannot be overridden by any flag.
  10. Refuses to modify files as root unless --allow-root.

Each of these is covered by a test in the repository. docs/safety.md explains what each one protects against and what happens when it fires.

Works with

amuxify does not replace anything in a typical self-hosted stack. It runs after the download client and before the library:

  • Download clients: SABnzbd, NZBGet, qBittorrent, Transmission, Deluge. Call amuxify from the post-processing script and use the exit code to fail the job.
  • Managers: Sonarr and Radarr custom scripts. Run on import and reject files that FAIL or BLOCK.
  • Media servers: Plex, Jellyfin, Emby, Kodi. They only ever see files that passed.
  • Storage: TrueNAS, Unraid, Synology and any NFS or SMB share. Ownership, mode and mtime are preserved in place, hardlinked files are skipped instead of broken, and the tool refuses to run as root unless told to.

Unattended use

amuxify never asks a question. Tracks with no language tag are handled by the languages.und profile key. Call it from your post-processing script and check the exit code. Built-in hook adapters for SABnzbd, NZBGet, Sonarr and Radarr are planned for 0.3.

amuxify remux --in-place "$SAB_COMPLETE_DIR" || exit 1

Example scripts for each tool are in docs/hooks.md.
