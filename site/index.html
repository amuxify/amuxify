amuxify

Checks downloaded video for malware, tracker junk and damage before it reaches your Plex or Jellyfin library.

A command-line tool that runs after SABnzbd, NZBGet, Sonarr or Radarr and before the library. It strips what does not belong in the file, never re-encodes, and exits with a verdict your download client can fail the job on.

$ amuxify scan ~/incoming
PASS  /home/me/incoming/Show.S01E01.mkv
WARN  /home/me/incoming/Movie.2019.mkv
      WARN  LINK_IN_TAG        1 link(s) in metadata: tag COMMENT: http://tracker.example/x
BLOCK /home/me/incoming/Movie.2019.Sub.mkv
      BLOCK ATTACH_EXEC        attachment #1 "font.ttf" (font/ttf, 71 KiB) contains executable PE/DOS executable

BLOCK: 3 file(s) BLOCK=1 PASS=1 WARN=1

The third file carries a Windows program disguised as a subtitle font. A media server would import it and a virus scanner would not flag it. amuxify blocks it.

What it catches

  • Programs disguised as fonts or images inside an MKV, and files that are a valid video and a valid ZIP, EXE or script at the same time.
  • Tracker and release-group links in tags, titles, chapter names and subtitles.
  • Your own account details in purchased files: account name, purchase date and store IDs in MP4 metadata.
  • Dangerous files next to the video: .lnk, .url, .exe, .scr, .bat, .ps1 and similar.
  • Broken or mislabeled files: wrong extension, truncated, no duration, does not decode.
  • Trick filenames with right-to-left override, zero-width characters or double extensions.

What a profile allows it to fix, it fixes: it strips metadata, drops commentary tracks, unwanted languages or attachments, sets language and default flags, and rebuilds the file as a clean MKV. Every kept stream is hashed and compared with the source before the new file replaces anything. It is not a transcoder, a renamer or a library manager.

Where it fits

  • SABnzbd and NZBGet: the best place. The hook runs before Sonarr or Radarr import, so a FAIL or BLOCK fails the job and nothing reaches the library. On a BLOCK, the arr blocklists the release and grabs another.
  • Sonarr and Radarr: the hook runs after import and cleans the file already in the library, with the original language taken from the series or movie. It cannot stop an import; use it when the download client is not yours to configure.
  • qBittorrent, Transmission, Deluge: they ignore a script's exit code. Use the Sonarr and Radarr hooks, or run amuxify scan --quarantine from the completion script to move BLOCK files out of the way.
  • Storage: TrueNAS, Unraid, Synology, NFS and SMB shares. Owner, mode and mtime are kept, and hard-linked files you are seeding are never edited in place.

The SABnzbd script is one line:

exec amuxify --profile homelab hook sabnzbd "$@"

Scripts for each tool ship in contrib/hooks/ and the Docker image. Setup steps are in docs/hooks.md.

Install

amuxify needs MKVToolNix 50 or newer and ffmpeg 4.4 or newer on the same machine. exiftool and clamscan are optional. amuxify doctor tells you what is missing.

# release binary, Linux and macOS (verifies the SHA-256 checksum)
curl -fsSL https://raw.githubusercontent.com/amuxify/amuxify/main/install.sh | sh

# Homebrew
brew install --cask amuxify/tap/amuxify

# Docker, run as the uid that owns the library, never root
docker run --rm -u 1000:1000 -v /srv/media/incoming:/data ghcr.io/amuxify/amuxify scan /data

The install guide covers package names per distro, pinning a version and the Docker image.

Safety

amuxify never overwrites a file, never follows a symlink and never re-encodes. If a kept stream's hash does not match the source, the output is deleted and the original stays. It refuses to run as root unless told to, and no flag overrides a BLOCK. There are ten guarantees in all, each with a test; docs/safety.md lists them.

Verdicts

VerdictExitMeaning
PASS0Nothing to report
WARN1Worth knowing; the file is usable
FAIL3Damaged: truncated, unparseable, mislabeled or a hash mismatch
BLOCK4Dangerous: executable payload, polyglot, trick filename or blocked sidecar

The worst verdict of the run is the exit code; 2 means a usage error and 130 an interruption. --json prints the full report, described in docs/report.md.
